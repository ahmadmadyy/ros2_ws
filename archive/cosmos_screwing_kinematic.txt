## Analysis

### 1. Tool-Tip Path Estimation
At key phase-transition timesteps, estimate tool0 [x,y,z] and orientation from joint angles and UR5e geometry (approximate FK). For each: timestep, joint config, estimated tool0 xyz, estimated orientation, expected position for that phase.

### 2. Geometric Constraint Verification

**Pick:** tool0 XY within ±0.012 m of screwdriver centre during descent; Z ≈ {grasp_z} m (±0.01) when gripper closes; orientation within ±5° of top-down.

**Transit:** tool-tip Z > table surface + 0.05 m at all times; path reasonably direct between pick and screw.

**Screw engagement:** tool0 XY within ±0.005 m of screw centre when lowering; screwdriver tip Z ≈ screw head Z (±0.005 m); orientation within ±2° of top-down.

**Screwing strokes:** tool0 XY within ±0.003 m of screw centre during CW rotation; Z constant (±0.002 m); only the tool z-axis rotation changes.

**Disengage/reposition:** tool lifted ≥ {approach_clearance} m before CCW; screwdriver tip clear of screw head during CCW; tool0 XY still aligned with screw (±0.005 m) before re-engage.

Report each as PASS / WARN / FAIL with observed values.

### 3. Workspace Boundary Check
Estimate: near full extension (elbow ≈ 0 or π), kinematic singularity risk, whether a different shoulder angle would be more comfortable.

### 4. Screwing Geometry Analysis
- **Axis alignment**: is wrist_3 axis aligned with screw axis during top-down engagement?
- **Lateral wobble**: estimate wobble radius from grasp offset; is it within screw-head tolerance?
- **Effective rotation**: total CW rotation minus any CCW applied while still engaged.

### 5. Collision Risk Assessment
- Screwdriver tip (90 mm below tool0) vs. table during transit
- Robot links vs. screwdriver in original position during transit
- Screwdriver tip vs. workpiece during lift-reposition cycles

## Common Structured Output

After completing the analysis above, output **only** this JSON block. Every field is required. Do not add extra fields.

```json
{
  "task_success":        {"score": <1-5>, "justification": "<one sentence>"},
  "phase_correctness":   {"score": <1-5>, "justification": "<one sentence>"},
  "screwing_quality":    {"score": <1-5>, "justification": "<one sentence>"},
  "anomaly_severity":    {"score": <1-5>, "justification": "<one sentence — 5=none found, 1=critical failure>"},
  "corrective_guidance": {"score": <1-5>, "justification": "<one sentence>"},
  "overall_score": <float 0.0-1.0>,
  "critical_failures": ["<string describing failure 1>", "<string describing failure 2>"],
  "recommended_waypoints": [
    {
      "phase": "<phase name>",
      "joints": [j1, j2, j3, j4, j5, j6],
      "gripper": <0.0-1.0>,
      "velocity_scaling": <0.0-1.0>,
      "note": "<which geometric constraint this waypoint satisfies or corrects>"
    }
  ]
}
```

Rules:
- `critical_failures`: array of short strings (one sentence each). Include **only CRITICAL severity** geometric constraint failures (FAIL status). Maximum 5 entries. If no critical failures, use `[]`.
- `recommended_waypoints`: 1–3 waypoints maximum. If all constraints pass, include the ideal S7:ENGAGE_SCREW waypoint at {screw_position}, tool0-z={grasp_z} m. If any FAIL, one corrective waypoint per failed constraint.
- Score guide: 5=excellent, 4=good, 3=acceptable, 2=poor, 1=critical failure.
- `overall_score` = (task_success×0.30 + phase_correctness×0.20 + screwing_quality×0.25 + anomaly_severity×0.15 + corrective_guidance×0.10) / 5.0
