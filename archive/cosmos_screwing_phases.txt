You observe a robot's joint trajectory during a screwdriver-pick-and-screw task and break it into semantic phases, assess whether each phase succeeded, and identify where the sequence deviated from the expected pattern.

## Analysis

### 1. Phase Segmentation
Break the trajectory into the expected semantic phases. For each phase, state the timestep range, what the robot did, and whether it succeeded.

Expected phase sequence:
1. **Home** — joints at rest at home configuration
2. **Open gripper** — gripper_state → 0.0
3. **Approach screwdriver** — arm moves to above screwdriver XY, tool0 Z > {grasp_z}
4. **Descend to grasp** — arm lowers to tool0 Z ≈ {grasp_z}
5. **Grasp** — gripper closes to ≈ {grasp_gripper_position} rad
6. **Retreat** — arm lifts with screwdriver; Z increases
7. **Move above screw** — arm transits to above screw XY at approach height
8. **Engage screw** — arm lowers to tool0 Z ≈ {grasp_z} at screw XY
9. **Screwing cycle × {n_cycles}** (each cycle):
   - 9a. **CW stroke** — wrist_3 decreases; other joints stationary
   - 9b. **Lift** — arm raises; wrist_3 frozen
   - 9c. **CCW reposition** — wrist_3 increases to ≈ {wrist3_safe_max}; arm stays lifted
   - 9d. **Re-engage** — arm lowers back to engage height (skipped on last cycle)
10. **Return home** — arm returns to home configuration

For each phase: `timestep_range`, `observed`, `expected`, `status` (COMPLETE / PARTIAL / MISSING / UNEXPECTED).

### 2. Task Success Assessment
- Did every phase complete in the correct order?
- Were there missing phases, repeated phases, or out-of-order transitions?
- Was wrist_3 within [{wrist3_safe_min}, {wrist3_safe_max}] throughout?
- Did the robot return home cleanly?

### 3. Spatial Reasoning
Explain how the robot moved through space: approach angle, transit efficiency between screwdriver and screw, alignment during engagement, and quality of lift-reposition cycles.

### 4. Phase-Level Anomaly Report
For each phase with status PARTIAL, MISSING, or UNEXPECTED: describe what went wrong, the impact on the task, and the severity (CRITICAL / WARNING / INFO).

### 5. Corrective Feedback
For each anomaly: which phase failed, why, and what concrete change would fix it.

## Common Structured Output

After completing the analysis above, output **only** this JSON block. Every field is required. Do not add extra fields.

```json
{
  "task_success":        {"score": <1-5>, "justification": "<one sentence>"},
  "phase_correctness":   {"score": <1-5>, "justification": "<one sentence>"},
  "screwing_quality":    {"score": <1-5>, "justification": "<one sentence>"},
  "anomaly_severity":    {"score": <1-5>, "justification": "<one sentence — 5=none found, 1=critical failure>"},
  "corrective_guidance": {"score": <1-5>, "justification": "<one sentence>"},
  "overall_score": <float 0.0-1.0>,
  "critical_failures": ["<string describing failure 1>", "<string describing failure 2>"],
  "recommended_waypoints": [
    {
      "phase": "<phase name>",
      "joints": [j1, j2, j3, j4, j5, j6],
      "gripper": <0.0-1.0>,
      "velocity_scaling": <0.0-1.0>,
      "note": "<why this waypoint and which phase it improves>"
    }
  ]
}
```

Rules:
- `critical_failures`: array of short strings (one sentence each). Include **only CRITICAL severity** phase failures (MISSING or clearly wrong phases). Maximum 5 entries. If no critical failures, use `[]`.
- `recommended_waypoints`: 1–3 waypoints maximum. If all phases succeeded, include the ideal screw-engagement waypoint at {screw_position}, tool0-z={grasp_z} m. If critical failures exist, one corrective waypoint per CRITICAL anomaly.
- Score guide: 5=excellent, 4=good, 3=acceptable, 2=poor, 1=critical failure.
- `overall_score` = (task_success×0.30 + phase_correctness×0.20 + screwing_quality×0.25 + anomaly_severity×0.15 + corrective_guidance×0.10) / 5.0
