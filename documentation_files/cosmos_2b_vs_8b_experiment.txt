Cosmos-Reason2-2B vs 8B — Screw Trace Analysis Experiment
Date: 2026-03-10

Prompt: cosmos_2b_vs_8b/prompt_screw_trace_analysis.txt
Script: cosmos_2b_vs_8b/run_cosmos_comparison.py


--- Goal ---

The purpose of this experiment was to determine whether the Cosmos
reasoning models are capable of understanding a robotics analysis task.
No assumption was made that either model had prior robotics knowledge —
the test was carried out in a purely zero-shot setting.

A joint-state trace from a UR robot performing a top-down screwing
operation with a Robotiq 85 gripper was provided as input. Both the 2B
and 8B variants were given the same prompt, which asked for a structured
analysis: a narration of the motion, identification of phases, a quality
verdict, anomaly detection, and an assessment of the screwing strategy.
The experiment was designed to find out whether Cosmos would grasp the
task at all, not to benchmark performance.


--- Setup ---

Both models were served through a local vLLM instance at
http://localhost:8000, using temperature 0.6 and max_tokens 4096.
The same prompt was sent to each model sequentially via the
OpenAI-compatible chat completions endpoint.

Output files:
  response_cosmos_reason2_2b_20260310_230711.txt / .json
  response_cosmos_reason2_8b_20260310_231022.txt / .json


--- Cosmos-Reason2-2B ---

Inference time: 15.2s
Response length: ~3,500 characters

A complete response was produced by the 2B model, covering all six
sections specified in the prompt: the trace narrative, phase table,
quality verdict, anomaly report, strategy assessment, and the final
JSON summary. The response was coherent and the domain vocabulary was
used correctly throughout — the significance of wrist_3 rotation was
acknowledged, the gripper state at end-of-task was flagged as
problematic, and the burst-and-pause screwing pattern was identified as
a sign of suboptimal control.

Correct observations:
- The screw-then-reset motion structure was identified
- The wrist_3 velocity spike at t=153.57s (+1.5675 rad/s) was flagged
- The gripper remaining closed at the end of the trace was noted
- Reset cycles were estimated to account for roughly 20% of total time
- Final verdict assigned: CONDITIONAL_PASS, quality score 6.5/10

Error found:
- Eight reset cycles were reported in the JSON summary. Only five are
  present in the trace. The count appears to have been inflated by
  conflating screwing bursts with full reset cycles. A discrepancy was
  also noted between the phase count in the table (9) and in the JSON
  (13), which suggests some internal inconsistency in how the output was
  assembled.

The 2B model can be considered to have understood the task. The reset
count error is a factual mistake, but the overall analysis was grounded,
the format was followed correctly, and the reasoning was traceable.


--- Cosmos-Reason2-8B ---

Inference time: 8.84s
Response length: ~1,271 characters

Only the final JSON block was returned by the 8B model. Sections one
through five — the narrative, phase table, verdict justification,
anomaly report, and strategy assessment — were absent from the response.
The model completed faster than the 2B, which likely reflects the
reduced amount of output that was generated rather than any advantage
in processing speed.

Contents of the returned JSON:
- reset_cycles_detected: 5  (correct)
- total_phases_identified: 8
- quality_score: 6.5, overall_verdict: CONDITIONAL_PASS
- The wrist_3 velocity spike and the closed gripper state were flagged
- understood_task: true

The values reported are largely accurate and the reset count is correct,
which the 2B model got wrong. However, no reasoning was provided to
support any of those values. Since sections one through five were
skipped entirely, there is no way to verify how the analysis was
arrived at. The understood_task field was set to true by the model
itself, but that self-assessment carries little weight when five of the
six required output sections were not produced.

--- Did both models understand the task? ---

2B: The task was understood. All output sections were produced, the
domain concepts were handled correctly, and the analysis could be
followed and critiqued. The reset count error is noted but does not
indicate a failure to comprehend what was being asked.

8B: This is harder to assess. The JSON values that were returned look
correct, but no analytical reasoning was provided alongside them. It
cannot be determined from the output alone whether the trace was
genuinely processed or whether the model defaulted to filling in the
JSON template with plausible values. The task cannot be considered
fully understood when five of the six requested sections were omitted.


--- Takeaways ---

The 2B model produced more useful output despite being the smaller of
the two. A structured report with one counting error is still a report
that can be reviewed and acted on. A JSON block with no supporting
analysis is not.

The 8B model's accuracy on the reset count is interesting and may
indicate stronger numerical reasoning at that scale, but without
accompanying explanation it does not translate into a more useful result
for an evaluation workflow.

Both models demonstrated some familiarity with robot motion concepts at
the vocabulary level. Whether that is sufficient for real evaluation
tasks is an open question — further testing with more varied traces and
possibly some degree of prompt engineering would be needed before any
strong conclusions can be drawn.
