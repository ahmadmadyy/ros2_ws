## Cosmos Variant A — State-Machine + Invariant Checking

**What makes it unique:** Treats the trajectory as a finite state machine. Each phase is a *state* with explicit entry conditions, invariants that must hold throughout, and exit conditions. The model must verify that every transition was legal and that no invariant was violated.

## State Machine Definition

The task is modeled as the following states. For each state, entry conditions, invariants, and exit conditions are defined.

| # | State | Entry Condition | Invariant | Exit Condition |
|---|-------|-----------------|-----------|----------------|
| S0 | HOME | start of task | joints ≈ home configuration | all joints at home |
| S1 | GRIPPER_OPEN | at home | gripper_state = 0.0 | gripper fully open |
| S2 | APPROACH_SCREWDRIVER | gripper open | tool0 XY ≈ screwdriver XY; Z > grasp_z; top-down orientation | tool0 above screwdriver at approach height |
| S3 | DESCEND_TO_GRASP | above screwdriver | tool0 XY ≈ screwdriver XY; orientation preserved; gripper open | tool0 Z ≈ grasp_z |
| S4 | GRASP | at grasp height | tool0 XY ≈ screwdriver XY; Z ≈ grasp_z | gripper_state ≈ grasp_gripper_position |
| S5 | RETREAT | gripper closed on screwdriver | tool0 XY ≈ screwdriver XY; gripper closed; orientation preserved | Z > grasp_z + retreat_height |
| S6 | MOVE_ABOVE_SCREW | holding screwdriver, above table | gripper closed; orientation preserved | tool0 XY ≈ screw XY; Z ≈ approach_z |
| S7 | ENGAGE_SCREW | above screw target | tool0 XY ≈ screw XY; gripper closed; orientation preserved | Z ≈ engage_z |
| S8 | CW_ROTATE | engaged with screw | joints[0:5] ≈ constant; wrist_3 decreasing; gripper closed; wrist_3 ≥ wrist3_safe_min | wrist_3 ≈ wrist3_safe_min |
| S9 | LIFT_DISENGAGE | CW stroke complete | tool0 XY ≈ screw XY; gripper closed | Z ≈ approach_z |
| S10 | CCW_REPOSITION | lifted above screw | Z ≈ approach_z (NOT engage_z); gripper closed; wrist_3 increasing | wrist_3 ≈ wrist3_safe_max |
| S11 | RE_ENGAGE | CCW done, not last cycle | tool0 XY ≈ screw XY; gripper closed | Z ≈ engage_z → return to S8 |
| S12 | FINAL_LIFT | last cycle complete | gripper closed | Z ≈ approach_z |
| S13 | RETURN_HOME | lifted after screwing | — | joints ≈ home configuration |

Valid transitions: S0→S1→S2→S3→S4→S5→S6→S7→S8→S9→S10→S11→S8 (repeat)... →S10→S12→S13

### 1. State Trace
Map each timestep range to a state from the table above. Produce a state trace like:
```

```

### 2. Invariant Verification

- **PASS**: invariant held throughout
- **WARN**: minor deviation (quantify the deviation)
- **FAIL**: invariant clearly violated (state timestep and values)

### 3. Transition Legality
For each observed state transition, check:
- Was the exit condition of the previous state met before transitioning?
- Was the transition in the set of valid transitions?
- Were there any illegal transitions (e.g., S10 at engage height, S8 with wrist_3 increasing)?

### 4. Cumulative Metrics
Compute:
- Total CW rotation (degrees and full turns)
- Number of complete cycles (S8→S9→S10→S11 or S8→S9→S10→S12)
- Total task duration
- Time spent in each state category (pick, screw, return)

### 5. Violations Summary
List all WARN and FAIL findings in a table:

| Severity | State | Timestep | Invariant/Condition | Expected | Observed |
|----------|-------|----------|---------------------|----------|----------|

### 6. Corrective Waypoints (if any FAIL found)
If any invariant was violated with severity FAIL, output corrective waypoints:
[
  {
    "phase": "<state name>",
    "joints": [j1, j2, j3, j4, j5, j6],
    "gripper": <value>,
    "velocity_scaling": <0.0–1.0>,
    "note": "<which invariant was violated and how this waypoint fixes it>"
  },
  ...
]

If all states passed, state "All invariants satisfied — no correction needed."

## Cosmos Variant B — Differential Analysis (Timestep-over-Timestep)

**What makes it unique:** Instead of segmenting into phases first, this prompt analyzes the *derivatives* of the trajectory — joint velocities, acceleration profiles, and change-point detection. ### 1. Joint Velocity Profile

  ω_i(t) = (θ_i(t+1) − θ_i(t)) / (timestamp(t+1) − timestamp(t))

Summarize the velocity profile for each joint as a sequence of motion segments:
- **Stationary**: |ω_i| < 0.01 rad/s
- **Slow motion**: 0.01 ≤ |ω_i| < 0.5 rad/s
- **Moderate motion**: 0.5 ≤ |ω_i| < 2.0 rad/s
- **Fast motion**: |ω_i| ≥ 2.0 rad/s

For each joint, produce a compact timeline:
```
joint_1: [t0–t20: stationary] [t21–t45: moderate +] [t46–t80: stationary] ...
joint_6 (wrist_3): [t0–t60: stationary] [t61–t90: slow −] [t91–t100: stationary] [t101–t115: fast +] ...
```
where + and − indicate direction.

### 2. Change-Point Detection
Identify all timesteps where a significant change occurs:
- A joint transitions between motion categories (stationary → moving or vice versa)
- The gripper state changes
- The dominant moving joint switches (e.g., from joints 1-3 moving to only joint 6 moving)

List each change-point with:
- Timestep
- Which joint(s) changed behavior
- Nature of change (started moving, stopped, reversed direction, gripper opened/closed)

### 3. Activity Inference
Using the change-points and velocity profiles, infer what the robot was doing in each segment. Use these motion signatures as guides:

| Motion Signature | Likely Activity |
|-----------------|-----------------|
| Joints 1-3 moving, 4-6 slow, gripper open | Arm repositioning (approach/transit) |
| Joints 1-3 moving downward, gripper open | Descending to grasp |
| Gripper state change (open→partial close) | Grasping screwdriver |
| Joints 1-3 moving upward, gripper closed | Lifting/retreating with tool |
| Only joint 6 (wrist_3) moving CW, all others stationary, gripper closed | Active screwing stroke |
| Joints 1-3 moving upward, joint 6 stationary, gripper closed | Lifting to disengage from screw |
| Only joint 6 (wrist_3) moving CCW, all others stationary, gripper closed | Wrist reposition (not screwing) |
| Joints 1-3 moving downward, gripper closed | Re-engaging screw for next stroke |

For each inferred segment, state:
- Timestep range
- Active joints and their velocity category
- Inferred activity
- Confidence (HIGH / MEDIUM / LOW) with reasoning

### 4. Anomaly Detection
Flag any of the following anomalies in the velocity profile:
- **Velocity spike**: Any joint |ω_i| > 5.0 rad/s (potential planning discontinuity)
- **Multi-joint screwing**: Joints other than wrist_3 moving significantly (|ω_i| > 0.05 rad/s) during inferred screwing segments
- **Wrong-direction screwing**: Wrist_3 moving CCW (increasing) while at engage height
- **Gripper instability**: Gripper state fluctuating during inferred screwing segments
- **Stall**: All joints stationary for > 2 seconds outside of expected pause points
- **Limit approach**: Any joint within 0.1 rad of its hard limit

For each anomaly, report: timestep, joint, observed value, expected behavior, severity (CRITICAL / WARNING / INFO).

### 5. Screwing Effectiveness Summary
From the wrist_3 velocity profile alone, compute:
- Number of distinct CW rotation segments (screwing strokes)
- Total CW angular displacement (sum of all CW-only segments)
- Total CCW angular displacement (sum of all CCW-only segments)
- Net rotation = total CW − total CCW (this should equal total effective screwing)
- Average CW angular velocity during screwing strokes
- Average CCW angular velocity during repositioning

### 6. Corrective Feedback
Based on anomalies found, provide specific corrections:
- If multi-joint screwing detected: suggest constraining joints 1-5 during wrist rotation
- If velocity spikes detected: suggest smoother trajectory interpolation between waypoints
- If wrong-direction screwing: suggest verifying lift height before CCW reposition
- If stalls detected: suggest checking IK solver convergence at those configurations
- If total net rotation is insufficient: suggest adding more cycles or increasing wrist range utilization

### 7. Corrective Waypoints (if needed)
If critical anomalies were found, output corrective waypoints:
[
  {
    "phase": "<inferred activity>",
    "joints": [j1, j2, j3, j4, j5, j6],
    "gripper": <value>,
    "velocity_scaling": <0.0–1.0>,
    "note": "<which anomaly this addresses>"
  },
  ...
]

If no critical anomalies, state "Trajectory is clean — no correction needed."

## Evaluator Variant C — Temporal Alignment Evaluator

**What makes it unique:** This evaluator focuses on the *temporal correspondence* between the Cosmos reasoning and the actual trajectory. It checks whether the phase boundaries, event timings, and causal ordering described in the reasoning actually match the recorded data. It penalizes hallucinated timing, out-of-order events, and missing temporal details, making it especially good at catching reasoning models that produce plausible-sounding but temporally inaccurate analyses.

```
You are a temporal alignment evaluator for robotic task analysis. You specialize in verifying whether a reasoning model's phase descriptions and event timing match the actual recorded joint trajectory data. Your focus is on temporal accuracy — did the model correctly identify *when* things happened?

## Task Context
- **Task description**: {task_description}
- **Robot**: {robot_description}
- **Screwdriver position**: {screwdriver_position}
- **Screw target position**: {screw_position}
- **Grasp height**: {grasp_z} m
- **Grasp gripper opening**: {grasp_gripper_position}
- **Grasp orientation**: {grasp_quaternion}
- **Number of screwing cycles**: {n_cycles}
- **Wrist_3 safe range**: [{wrist3_safe_min}, {wrist3_safe_max}] rad
- **CW step size**: {screw_step_rad} rad

## Inputs

### Cosmos Reasoning Output:
{cosmos_reasoning_text}

### Joint Trajectory:
{joint_trajectory_json}

Fields per timestep: `timestamp`, `joints` [j1..j6] in radians, `gripper_state` (0.0=open, 1.0=closed).

## Evaluation Procedure

### Step 1: Extract Cosmos Timeline
Parse the Cosmos reasoning output and extract every temporal claim as a structured event:
```
[
  {"event": "<description>", "cosmos_timestep_range": [start, end], "cosmos_values": {...}},
  ...
]
```

Include events such as:
- Phase boundaries (e.g., "approach starts at t=12, ends at t=25")
- Specific joint values at specific times (e.g., "wrist_3 = -5.2 rad at t=80")
- Gripper events (e.g., "gripper closes at t=35")
- Cycle boundaries (e.g., "cycle 2 CW stroke from t=120 to t=155")
- Cumulative metrics at specific points (e.g., "450° of CW rotation by end of cycle 2")

### Step 2: Ground Truth Timeline
From the actual trajectory data, independently compute the same events:
- Detect phase boundaries by monitoring joint velocity changes and gripper state changes
- Record actual wrist_3 values at each timestep
- Record actual gripper state transitions with exact timesteps
- Compute cumulative CW rotation at cycle boundaries

### Step 3: Temporal Alignment Scoring
For each event extracted from the Cosmos output, compute:

**Boundary Alignment Error (BAE):**
For phase boundary claims: BAE = |cosmos_start - actual_start| + |cosmos_end - actual_end| (in timesteps)
- EXACT: BAE = 0
- CLOSE: BAE ≤ 4
- APPROXIMATE: BAE ≤ 10
- MISALIGNED: BAE > 10
- HALLUCINATED: the event doesn't exist in the trajectory at all

**Value Alignment Error (VAE):**
For joint value claims: VAE = |cosmos_value - actual_value| (in radians or appropriate unit)
- EXACT: VAE < 0.01
- CLOSE: VAE < 0.1
- APPROXIMATE: VAE < 0.5
- WRONG: VAE ≥ 0.5
- HALLUCINATED: the claim references a timestep/joint that doesn't exist

**Order Alignment:**
For event sequences, verify that the Cosmos output preserves the correct causal ordering:
- Did grasp happen before retreat? (order check)
- Did CW rotation happen before lift in each cycle? (order check)
- Did CCW reposition happen before re-engage? (order check)
- Did engage happen before CW rotation in each cycle? (order check)
For each pair: CORRECT or INVERTED

### Step 4: Coverage and Hallucination Analysis

**Coverage:** What fraction of actual trajectory events did the Cosmos output mention?
- Count actual phases/events from the trajectory
- Count how many the Cosmos output addressed
- Coverage = addressed / total

**Hallucination rate:** What fraction of Cosmos claims don't correspond to real trajectory events?
- Count total claims in Cosmos output
- Count claims with HALLUCINATED alignment
- Hallucination rate = hallucinated / total

**Missing events:** List significant trajectory events that the Cosmos output failed to mention:
- Unreported anomalies
- Skipped cycles
- Unmentioned gripper events

### Step 5: Temporal Consistency Check
Verify internal consistency of the Cosmos timeline:
- Do the reported phase durations sum to approximately the total task duration?
- Are the reported cycle durations roughly consistent with each other?
- Do the reported wrist_3 start/end values per cycle chain correctly (end of CCW reposition should match start of next CW stroke)?
- Does the reported cumulative rotation match the sum of individual stroke rotations?

For each consistency check: CONSISTENT or INCONSISTENT (with explanation).
